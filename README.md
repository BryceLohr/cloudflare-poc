# Hello World on Cloudflare Workers

A minimal Cloudflare application: a Worker serving a JSON API, with a static
frontend served straight from Cloudflare's edge.

## Layout

| Path | Purpose |
| --- | --- |
| `wrangler.jsonc` | Worker config (name, entrypoint, compatibility date, assets) |
| `src/index.ts` | Worker entrypoint — handles `/api/hello` |
| `public/index.html` | Static frontend, served from the edge |
| `test/index.spec.ts` | Tests running inside the real Workers runtime |

Requests are matched against `public/` first; anything that isn't a static file
falls through to the Worker.

## Develop

```sh
npm install
npm run dev      # http://localhost:8787
```

## Test & typecheck

```sh
npm test         # Vitest, running in workerd via Miniflare
npm run typecheck
```

## Deploy

Authenticate once, then deploy:

```sh
npx wrangler login
npm run deploy
```

This publishes to `<name>.<your-subdomain>.workers.dev`. For CI, set a
`CLOUDFLARE_API_TOKEN` environment variable instead of `wrangler login`.

## Notes

- `compatibility_date` is pinned to a date the installed `workerd` supports.
  Bump it (and rerun `npm run cf-typegen`) as you upgrade Wrangler.
- `worker-configuration.d.ts` is generated by `npm run cf-typegen` and committed
  so typechecking works on a fresh clone.
